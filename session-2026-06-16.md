## Tasks completed

### 1. Inbox "My Inputs" empty state — two-state differentiation
**Problem:** The Inbox had a single empty state that didn't distinguish between first-time users (FTUE) and users who had assigned all their inputs to projects.

**Solution:** Computed `hasAnyManualInputs` from the full workspace `inputs` array (not Inbox-scoped) to branch between two states:
- **FTUE (zero inputs ever):** "Your inbox is empty. Add your first input manually, or capture signals from the web with the Chrome extension."
- **All assigned:** "All your inputs have been added to a project. Add more from the web with the Chrome extension."

Table structure (header row) is always rendered in list mode — empty state content goes inside a `manualEmptyContent` variable rendered in the body, preserving column alignment.

### 8. Disaggregate Signal Quality → Signal Strength + Source Confidence
**The largest task of the session.** Replaced the single `signal_quality` field with two practitioner-set fields across every surface in the app.

**New fields:**
- **Signal Strength** — `Weak / Moderate / Strong` — practitioner's assessment of the signal's evidential weight
- **Source Confidence** — `Low / Medium / High` — practitioner's trust in the source

**Design rationale:** These are distinct judgements that get conflated in a single quality field. A strong signal can come from a low-confidence source; separating them gives practitioners more nuanced control.
